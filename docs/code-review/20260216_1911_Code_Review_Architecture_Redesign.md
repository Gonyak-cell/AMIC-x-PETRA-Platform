# 코드 리뷰 시스템 아키텍처 재설계

**플랜 작성일**: 2026-02-16 19:02:58
**목표**: 멀티 에이전트 코드 리뷰 시스템의 허위 양성과 과도한 평가 감소

---

## 배경

현재 코드 리뷰 시스템은 Verified Claim Protocol(VCP), 멀티 에이전트 아키텍처, 교차 검증 등 **강력한 기반**을 갖추고 있습니다. 그러나 종합 분석 결과 **체계적인 허위 양성 원인**과 **과도한 평가 패턴**이 발견되었습니다.

### 핵심 문제점

1. **백엔드 코드 드리프트** (높은 위험도)
   - API/Security auditor가 백엔드 코드 가용성을 확인하지 않고 참조
   - 0단계에 백엔드 디렉터리 존재 여부 체크 없음 → 환각 위험
   - 영향: 백엔드 코드 미제공/이동 시 허위 양성 급증

2. **에이전트 범위 확장** (높은 위험도)
   - 에이전트가 광범위한 7개 카테고리 체크리스트 보유
   - 리뷰 대상 코드 유형과 무관하게 획일적 적용
   - 영향: 유틸 함수에서 UI/UX 패턴 누락 플래그

3. **신뢰도 점수 미활용** (중간 위험도)
   - VCP가 이슈별 HIGH/MEDIUM/LOW 신뢰도 요구
   - 하지만 우선순위는 심각도만 사용
   - 영향: 중간 신뢰도 치명적 이슈와 높은 신뢰도 치명적 이슈 동일 취급

4. **불완전한 검증 범위** (중간 위험도)
   - 2단계 교차 검증이 치명적+중요 이슈만 검사 (전체의 ~30%)
   - 보통/경미 이슈(70%)는 미검증 → 허위 양성 비율 불명
   - 영향: 낮은 심각도 허위 양성 누적, 노이즈 증가

5. **불투명한 거부 보고** (낮은 위험도)
   - "거부된 가설: N건" 보고되나 맥락 없음
   - 패턴 식별 불가 (구현됨 vs 환각 vs 논리 오류)
   - 영향: 허위 양성 비율 개선 여부 추적 불가

### 왜 재설계가 필요한가?

시스템이 VCP 5단계 검증으로 **허위 양성 방지**를 목표로 설계되었으나, 구현 공백으로 허위 양성이 누수됩니다. 이 재설계는 **하위 호환성을 유지**하면서 **누락된 보호 장치**를 추가합니다.

### 2단계: 신뢰도 가중 우선순위

**목표**: VCP 신뢰도 점수를 우선순위 계산에 활용

#### 2.1 복합 우선순위 공식 정의

**공식**:
```
우선순위 점수 = (심각도 가중치 × 신뢰도 가중치) + 보너스

심각도:
- Critical: 100
- Major: 70
- Moderate: 40
- Minor: 20

신뢰도:
- HIGH: 1.0
- MEDIUM: 0.6 (40% 하향)
- LOW: 0.3 (70% 하향)

보너스:
- 교차 검증(2+ 에이전트): +10
- review-verifier 확인: +15

우선순위 등급:
- P0: 90+
- P1: 60-89
- P2: 30-59
- P3: <30
```

**예시**: Critical + MEDIUM 신뢰도 = 100 × 0.6 = 60 → **P1** (P0 아님!)

**수정 파일**: `amic-platform/.claude/rules/verified-claim-protocol.md`

**목표**: 보통/경미 이슈 검증 (현재 0% 검증)

**신규 파일**: `amic-platform/.claude/skills/auto-verify/SKILL.md`

보통+경미 이슈용 경량 자동 검증:
1. **파일 존재**: Glob 체크
2. **라인 검증**: 파일 ±10줄 Read, 라인 번호 ±5 이내 확인

점수: 파일(+25) + 라인(+25) + 매칭(+50) → ≥75 = 검증됨, <75 = 수동 검토 플래그

## 구현 우선순위

### 즉시 (1주차) — 높은 영향, 낮은 노력
1. **백엔드 가용성 체크** (1단계 일부)
   - review-orchestrate에 백엔드 디렉터리 Glob 체크 추가
   - api-auditor/security-auditor에 `backend_available` 플래그 전달
   - 효과: 대부분의 환각 허위 양성 방지

2. **신뢰도 가중 우선순위** (2단계 완료)
   - 3단계(리포트 조립)에 공식 구현
   - 효과: 중간 신뢰도 치명적 이슈가 더 이상 P0 아님 → 허위 긴급성 감소

3. **거부 카테고리** (5단계 완료)
   - VCP 템플릿에 분류 테이블 추가
   - 효과: 허위 양성 패턴 가시성 → 반복적 개선

### 단기 (2-3주차) — 중간 노력
4. **범위-에이전트 필터링** (1단계 일부)
   - 파일 패턴 → 에이전트 호환성 매트릭스 구현
   - 효과: 범위 확장 허위 양성 감소

5. **에이전트 추론 감사 추적** (4단계 일부)
   - VCP 이슈 형식에 검증 추적 요구사항 추가
   - 효과: 에이전트의 VCP 준수를 감사 가능하게 만듦

### 중기 (4-6주차) — 높은 노력
6. **자동 검증 스킬** (3단계 완료)
   - 보통+경미 이슈용 경량 검증 구현
   - 효과: 검증 범위를 30%에서 100%로 증가

7. **스키마 드리프트 탐지** (1단계 일부)
   - 프론트엔드 타입 vs 백엔드 스키마 비교
   - 효과: 스키마 진화로 인한 api-auditor의 비이슈 플래그 방지

### 장기 (선택사항) — 낮은 우선순위
8. **목 데이터 최신성** (1단계 일부)
9. **전체 10개 에이전트 파일 업데이트** (4단계) — 점진적 수행 가능

## 검증 전략

### 테스트 계획

1. **기준 허위 양성 비율**
   - 검증된 양호 코드에서 현재 시스템 실행
   - 허위 양성을 수동으로 카운트 → 기준선 설정

2. **점진적 테스트**
   - 각 단계 후 동일한 코드 재실행
   - 측정: 허위 양성 감소, 검증 범위 증가

3. **백엔드 미제공 테스트**
   - 임시로 `Auto FDD` 디렉터리 이름 변경
   - `/review-security` 실행 → 낮은 신뢰도 경고 예상
   - 디렉터리 복원 → 정상 작동 확인

4. **신뢰도 하향 테스트**
   - 중간 신뢰도 치명적 이슈 찾기
   - 우선순위 매트릭스에서 P1(P0 아님)인지 확인

5. **자동 검증 정확도**
   - 5개의 가짜 보통 이슈 수동 주입
   - auto-verify 실행 → 5개 모두 플래그 예상

### 성공 지표

- **허위 양성 비율**: 목표 <10% (현재 불명이나 20-30%로 추정)
- **검증 범위**: 100% (현재 30%)
- **신뢰도 정렬**: P0 이슈의 90%+ 높은 신뢰도 보유
- **백엔드 허위 양성 방지**: 백엔드 미제공 시 환각 허위 양성 0건

2. **신뢰도 공식이 너무 공격적**: 3단계에서 심각도만 사용하도록 복원 (1줄 변경)

4. **에이전트 추적 노이즈**: 리포트 마크다운에서 추적을 접을 수 있게 만들기 (`<details>` 태그 사용)

모든 변경은 기존 시스템에 **추가적**이므로 → 핵심 기능을 깨지 않고 비활성화 가능.
