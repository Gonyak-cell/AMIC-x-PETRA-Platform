# AMIC x PETRA Platform — 통합 플랫폼 구현 계획서

## 1. 개요

AMIC Law 내부 3개 프로젝트(Auto FDD, KIIS, IM Module)를 하나의 React SPA 프론트엔드로 통합한다.
백엔드는 각각 독립 서버로 운영하며, 프론트엔드에서 Vite Proxy/nginx를 통해 분기한다.

```
브라우저 ──→ React SPA (amic-platform)
                 │
                 ├── /api/fdd/*  → FDD 백엔드 :8000  (FastAPI + PostgreSQL)
                 ├── /api/kiis/* → KIIS 백엔드 :8001  (FastAPI + PostgreSQL + Redis + ES)
                 └── /api/im/*   → IM 백엔드 :8002   (FastAPI + PostgreSQL + Redis + Celery)
```

## 2. 각 모듈 장단점 분석

### 2-1. Auto FDD (재무 실사)

**역할**: M&A 재무 실사(Financial Due Diligence) 자동화

| 장점 | 단점 |
|------|------|
| 유일한 프론트엔드 보유 (14페이지, 10훅, 9타입, 6컴포넌트) | DealListPage 페이지네이션 미구현 |
| UI 컴포넌트 라이브러리 완비 (Button, Card, DataTable 등 14개) | React Error Boundary 없음 |
| JWT 인증 + auto-refresh + 중복 refresh 방지 | 훅 팩토리 없음 (모듈마다 훅 직접 작성) |
| 금융 전용 차트 3종 (FinancialBarChart, TrendLineChart, WaterfallChart) | 사이드바 네비게이션 하드코딩 |
| 접근성 지원 (ARIA label, 키보드 네비게이션) | 클라이언트 폼 검증 부재 |
| 백엔드 17개 라우터 완전 연동 상태 | — |
| Docker + Nginx 멀티스테이지 빌드 완비 | — |

**결론**: 통합 플랫폼의 기반(Base)으로 사용. 모든 패턴의 레퍼런스 구현.

### 2-2. KIIS (투자 인텔리전스)

**역할**: DART/KOFIA/리츠 데이터 기반 투자정보 통합 인텔리전스

| 장점 | 단점 |
|------|------|
| 백엔드 14개 라우터 구현 완료 | 프론트 타입이 백엔드 Pydantic 스키마와 불일치 (필드명 5건) |
| 프론트엔드 12페이지 모두 구현됨 (실제 API 연동) | Money Rules 위반: 금액 필드를 number로 정의 (string이어야 함) |
| 10개 훅 모두 TanStack Query v5 패턴 준수 | REIT 타입 핵심 필드 6개 누락 (total_assets 등) |
| 5개 전용 컴포넌트 (ReputationBadge, SentimentIndicator 등) | 백엔드 기능 중 미노출 4개 도메인 (Portfolio, Managers, Entity, Disclosures) |
| Elasticsearch 기반 통합 검색 | Sanction 타입에 corp_code/corp_name 누락 |
| AI 제재 분류 + 평판 분석 기능 | — |

**결론**: 프론트엔드 거의 완성(95%). 타입을 백엔드 스키마에 맞춰 교정하는 것이 핵심 작업.

### 2-3. IM Module (투자설명서 생성기)

**역할**: M&A Information Memorandum(IM) 자동 생성

| 장점 | 단점 |
|------|------|
| 백엔드 99% 완성 (951개 테스트 통과) | 빌드 실패 — import하는 파일 3건 누락 |
| Celery 비동기 6단계 파이프라인 (수집→분석→생성→렌더링) | 3단계 위저드 (계획서 원안은 4단계) |
| PPTX/PDF 자동 생성 (python-pptx, WeasyPrint) | TemplatesPage 하드코딩 (CRUD 미구현) |
| 프론트-백엔드 스키마 99% 일치 | useCompanies 훅 파일 누락 |
| 폴링 기반 진행률 추적 (3초 간격 자동 갱신) | PipelineStatus, ImTemplate 등 타입 미정의 |
| 4가지 IM 스타일 지원 (TITAN/COVENANT/FULL/CUSTOM) | — |

**결론**: 백엔드 최고 수준. 프론트엔드 누락 파일 3개 보충이 최우선 과제.

## 5. 인증 전략

**추천: Shared JWT Secret**

```
                JWT Token (FDD에서 발급)
                      │
      ┌───────────────┼───────────────┐
      ↓               ↓               ↓
    FDD :8000      KIIS :8001      IM :8002
    JWT 검증       JWT 검증        JWT 검증
    같은 SECRET    같은 SECRET     같은 SECRET
```

- **1단계 (개발)**: FDD 인증 기본 사용. KIIS/IM은 `AUTH_ENABLED=False`
- **2단계 (배포)**: 3개 백엔드에 동일 `JWT_SECRET` 환경변수 공유

프론트엔드는 FDD에서 받은 토큰 하나로 3개 백엔드 모두 접근한다.
IM 백엔드는 자체 JWT 구현 완료, KIIS도 JWT middleware 존재 — SECRET만 통일하면 호환된다.

### Phase E: 인프라 (배포 준비)

| # | 생성 파일 | 설명 |
|---|-----------|------|
| E1 | `docker-compose.yml` (루트) | 전체 서비스 오케스트레이션 |
| E2 | `nginx/default.conf` | 프로덕션 리버스 프록시 |
| E3 | `.env.example` | 환경변수 템플릿 |

**docker-compose 서비스 구성**:

```yaml
services:
  frontend:          # nginx + React 빌드 결과물 → :80
  fdd-api:           # Auto FDD FastAPI → :8000
  kiis-api:          # KIIS FastAPI → :8001
  im-api:            # IM Module FastAPI → :8002
  celery-worker:     # IM Celery 워커
  postgres-fdd:      # FDD DB → :5432
  postgres-kiis:     # KIIS DB → :5433
  postgres-im:       # IM DB → :5434
  redis:             # KIIS 캐시 + IM Celery 브로커 → :6379
  elasticsearch:     # KIIS 검색 엔진 → :9200
```

**nginx 프록시 설정**:

```nginx
server {
    listen 80;

    location /api/fdd/  { proxy_pass http://fdd-api:8000/api/v1/; }
    location /api/kiis/ { proxy_pass http://kiis-api:8001/api/v1/; }
    location /api/im/   { proxy_pass http://im-api:8002/api/v1/; }

    location / {
        root /usr/share/nginx/html;
        try_files $uri /index.html;
    }
}
```

```
Phase A (IM 빌드 복구)     ─── 즉시 ──→  npm run build 통과

     │
Phase D (크로스 모듈 연동)  ─── 보통 ──→  통합 플랫폼 가치 실현
     │
Phase E (인프라)           ─── 낮음 ──→  배포 준비
```

- **Phase A + Phase B**는 독립적이므로 병렬 진행 가능
- **Phase D**는 A, B 완료 후 진행
- **Phase E**는 언제든 독립 진행 가능

## 10. KIIS 백엔드 미노출 기능 (추후 확장)

현재 KIIS 백엔드에는 14개 라우터가 있으나 프론트엔드에서 10개만 사용 중이다.
아래 4개는 추후 페이지 추가 시 활용 가능하다.

| 백엔드 라우터 | 엔드포인트 예시 | 용도 |
|---------------|-----------------|------|
| Portfolio | `GET /portfolio/by-investor/{corpCode}` | 포트폴리오 생존 분석, 유니콘 추적 |
| Managers | `GET /managers/movements` | 키맨 이동 추적, 운용인력 프로필 |
| Entity | `POST /entities/resolve` | 기업명 퍼지 매칭, 별칭 관리 |
| Disclosures | `GET /disclosures/{corpCode}` | 공시 상세, DART/KOFIA 딥링크 |

## 11. 미결정 사항

| 항목 | 선택지 | 현재 추천 | 결정 방법 |
|------|--------|-----------|-----------|
| Money Rules 적용 | string vs number | 백엔드 응답 확인 후 | KIIS 백엔드 실행 → JSON 응답 타입 확인 |
| IM 위저드 단계 | 3단계 유지 vs 4단계 확장 | 3단계 유지 | IM 백엔드 API와 정합 |
| IM 템플릿 CRUD | 하드코딩 vs API 연동 | 하드코딩 유지 | 백엔드에 /templates 없음 |
| KIIS 추가 기능 | Portfolio/Managers 페이지 | 추후 | 우선순위에 따라 |
| CompanyDetail 레이아웃 | 현재 섹션 vs 탭 UI | 현재 유지 | UX 피드백 후 |

## 12. 기술 스택 (확정)

| 카테고리 | 기술 |
|----------|------|
| Framework | React 19 + TypeScript 5.7 (strict) |
| Build | Vite 6 |
| Routing | React Router v7 (lazy loading) |
| State | TanStack Query v5 |
| Styling | Tailwind CSS 3.4 (AMIC 브랜드 토큰) |
| Charts | Recharts 3 |
| Icons | Lucide React |
| HTTP | Axios (팩토리 패턴) |
| Auth | JWT + refresh token (Shared Secret) |
| Toast | Sonner |
| Deploy | Docker + Nginx 리버스 프록시 |
