# FDD/MA 502 Bad Gateway 수정

> 작성: 2026-02-26 14:29

## 문제 요약

프로덕션 환경에서 FDD(`/api/fdd/*`)와 MA(`/api/ma/*`)가 502 Bad Gateway 반환.
KIIS, IM은 정상 동작.

사용자 증상: 로그인 페이지에서 "Invalid email or password" 오류 (실제로는 FDD API 404 → 502).

## 근본 원인 확정

### 원인 1: Docker BuildKit 이미지 스왑 (Primary)

- **위치**: `.github/workflows/deploy.yml` 빌드 단계
- **원인**: 커밋 `0a432ff`에서 `--no-cache` 플래그를 제거함. BuildKit이 fdd-api와 deal-mgmt-api 이미지를 병렬 빌드 시 캐시 레이어를 공유하며 최종 이미지가 뒤바뀜.
- **증거**:
  1. FDD 헬스체크가 `"service":"deal-mgmt"` 반환 (deal-mgmt 코드가 FDD 컨테이너에서 실행)
  2. MA 헬스체크가 `"version":"0.1.0"` 반환 (FDD 코드가 MA 컨테이너에서 실행)
  3. FDD Dockerfile은 Python 3.12, deal-mgmt는 Python 3.11 사용 — 이미지 구분 가능
  4. FDD는 `postgresql://` (psycopg2), MA는 `postgresql+asyncpg://` — 스왑 시 DB 드라이버 불일치로 크래시
  5. 헬스체크는 DB 미접근이라 통과하지만, 이후 DB 요청 시 크래시 → 502

### 원인 2: 메모리 과다 사용 가능성 (Secondary)

- **위치**: `docker-compose.prod.yml` — FDD/MA 모두 `--workers 4`
- **원인**: Azure VM E2s_v3 (2 vCPU, 16GB RAM)에서 전체 컨테이너 메모리 합계 ~14GB. 4 workers × 2 서비스 = OOM 가능성.
- **계산**: 각 worker ~400MB × 4 = 1.6GB/서비스, 전체 14GB 중 여유 2GB 미만

## 수정 내역

### 1. `--no-cache` 복원 (`.github/workflows/deploy.yml`)

```yaml
# Before (0a432ff)
$COMPOSE build $SERVICES

# After
$COMPOSE build --no-cache $SERVICES
```

메인 빌드와 롤백 빌드 모두 `--no-cache` 적용.

### 2. Workers 4→2 감소 (`docker-compose.prod.yml`)

```yaml
# FDD
command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2

# MA (deal-mgmt)
command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
```

- 메모리 사용량 ~50% 감소 (서비스당 ~800MB → ~400MB)
- 2 vCPU VM에서 4 workers는 과도 — 2 workers가 적절

### 3. 안정성 재확인 추가 (`deploy.yml` Step 7/8)

헬스체크 통과 후 30초 대기 → 모든 서비스 재확인. 배포 직후 크래시를 감지.

```bash

  # 헬스체크 재실행 → STABLE/CRASHED 판정
done
```

### 4. 컨테이너 로그 캡처 추가 (`deploy.yml` Step 8/8)

배포 성공/실패 무관하게 항상 수집:
- `docker stats --no-stream` (메모리/CPU 스냅샷)
- 각 서비스 최근 30줄 로그
