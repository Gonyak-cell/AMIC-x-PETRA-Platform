# Production Error Catalog

> 프로덕션 에러 발생 시 빠른 참조를 위한 카탈로그.
> 마지막 업데이트: 2026-02-26 12:31

## 사용법

1. 에러 증상에 해당하는 카테고리 찾기
2. "점검 대상"과 "수정 방법" 참고
3. **반드시** 동일 카테고리의 다른 모듈도 함께 점검
4. `scripts/diagnose-production.sh` 실행으로 전체 검증

---

## 카테고리 1: 인증 실패 (401)

**증상**: 로그인 후 특정 모듈 API에서 401 Unauthorized 응답

**근본 원인**: 모듈간 JWT_SECRET 불일치 (FDD에서 발급한 토큰을 다른 모듈이 검증 불가)

**점검 대상** (전체 4개 API):
```bash
# 모든 API의 JWT_SECRET 동일 여부 확인
for svc in fdd-api kiis-api im-api deal-mgmt-api; do
  docker compose exec -T $svc env | grep JWT_SECRET
done
```

**수정**:
- `docker-compose.prod.yml`의 해당 서비스에 `JWT_SECRET: ${SHARED_JWT_SECRET}` 추가
- `docker compose up -d --no-deps <service>`

**사례**: 2026-02-26 KIIS (a331a6f), IM (4ef1860)

---

## 카테고리 2: 권한 오류 (403)

**증상**: 인증은 성공하나 특정 엔드포인트 접근 거부

**근본 원인**: 사용자 역할/권한 미부여, 미들웨어 설정 오류

**점검 대상**:
- 각 모듈의 auth 미들웨어/의존성 설정
- 사용자 DB에서 역할(role) 확인

---

## 카테고리 3: 라우팅 오류 (404)

**증상**: API 엔드포인트 404 Not Found

**근본 원인**: nginx upstream 미매핑, 라우터 미등록

**점검 대상**:
- `nginx/prod.conf` + `nginx/prod-nossl.conf`의 location 블록
- 각 백엔드의 라우터 등록 (`app.include_router()`)

---

## 카테고리 4: 검증 실패 (422)

**증상**: 폼 제출 시 422 Unprocessable Entity

**근본 원인**: Pydantic 요청 스키마와 실제 요청 본문 불일치

**점검 대상**:
- 백엔드 Pydantic 모델의 필드명/타입
- 프론트엔드 API 호출 시 전송하는 JSON 키/값

**모듈별 422 발생 경로**:
| 모듈 | 경로 | 설명 |
|------|------|------|
| FDD | `FDDError` 기본값 | 도메인 에러 422 반환 (exceptions.py:51) |
| IM | `ValidationError` | API 검증 에러 (\_\_init\_\_.py:42) |
| MA | `WorkflowError` | 상태 전환 실패 (exceptions.py:103) |
| KIIS | FastAPI 자동 | Pydantic 검증만 |

## 카테고리 5: DB 연결 실패 (500)

**증상**: 전체 또는 특정 모듈 API 500, health의 `migration_ok: false`

**근본 원인**: PostgreSQL 비밀번호 불일치 (Docker 볼륨 재사용 시 발생)

**점검 대상** (전체 4개 DB):
```bash
# 모든 DB에서 SELECT 1 실행
docker compose exec -T fdd-db psql -U autofdd -d autofdd -c "SELECT 1"
docker compose exec -T kiis-db psql -U kiis_user -d kiis -c "SELECT 1"
docker compose exec -T im-db psql -U postgres -d imgen -c "SELECT 1"
docker compose exec -T deal-mgmt-db psql -U deal_mgmt_user -d deal_mgmt -c "SELECT 1"
```

**수정**:
```bash
docker exec <db-container> psql -U <user> -d <db> -c "ALTER USER <user> WITH PASSWORD '<.env의 비밀번호>';"
```

**중요**: Docker PostgreSQL은 **최초 볼륨 생성 시에만** `POSTGRES_PASSWORD` 적용.

**사례**: 2026-02-26 FDD/KIIS/MA (bb03717)

## 카테고리 6: 마이그레이션 오류 (500)

**증상**: `alembic upgrade head` 실패, `migration_ok: false`

**근본 원인**: Alembic `down_revision` 불일치, 중복 인덱스, 체인 단절

**점검 대상** (전체 4개 모듈):
```bash
for svc in fdd-api kiis-api im-api deal-mgmt-api; do
  docker compose exec -T $svc alembic current
  docker compose exec -T $svc alembic heads
done
```

**주의사항**:
- `down_revision`은 정확한 revision ID 문자열이어야 함
- `sa.Column(index=True)` + `op.create_index()` 동시 사용 금지

**사례**: 2026-02-26 deal-mgmt 체인 단절 (a331a6f), 중복 인덱스 (7fca584)

## 카테고리 7: 게이트웨이 오류 (502)

**증상**: nginx 502 Bad Gateway

**근본 원인**: 백엔드 컨테이너 미시작, 크래시, 또는 포트 불일치

**점검 대상**:
```bash
docker compose ps   # 컨테이너 상태 확인
docker compose logs <service> --tail=50  # 에러 로그 확인
```

---

## 카테고리 8: 서비스 불가 (503)

**증상**: API 503 Service Unavailable

**근본 원인**: 리소스 부족, 커넥션 풀 고갈, 과부하

**점검 대상**:
```bash
free -h               # 메모리
df -h                 # 디스크
docker stats --no-stream  # 컨테이너별 리소스
```

---

## 카테고리 9: CORS 오류

**증상**: 브라우저 콘솔에 CORS policy 에러

**근본 원인**: 환경변수명/형식 불일치

**점검 대상** — 모듈별 형식이 다르므로 **반드시 전체 확인**:

| 모듈 | 환경변수명 | 타입 | .env 형식 |
|------|----------|------|----------|
| FDD | `CORS_ORIGINS` | str (쉼표) | `https://ap-platform.kr,http://52.231.69.38` |
| KIIS | `ALLOWED_ORIGINS` | list[str] (JSON) | `["https://ap-platform.kr","http://52.231.69.38"]` |
| IM | `CORS_ORIGINS` | list[str] (JSON) | `["https://ap-platform.kr","http://52.231.69.38"]` |
| MA | `ALLOWED_ORIGINS` | list[str] (JSON) | `["https://ap-platform.kr","http://52.231.69.38"]` |

**사례**: 2026-02-26 KIIS 환경변수명 불일치 (4ef1860)

## 카테고리 10: CSP/보안 헤더 차단

**증상**: 프론트엔드 스크립트 실행 불가, 콘솔에 CSP 위반

**근본 원인**: nginx CSP 정책 제한

**점검 대상**: `nginx/prod.conf` + `nginx/prod-nossl.conf` **동시** 확인
- 두 파일의 CSP 설정이 동일해야 함

**사례**: 2026-02-26 script-src 'self' 'unsafe-inline' 누락 (4ef1860)

---

## 카테고리 11: 로그인 불가 (쿠키/인증)

**증상**: 로그인 폼 제출 후 인증 안 됨

**근본 원인**: 쿠키 Secure/SameSite 설정, ENV 환경변수 미설정

**점검 대상**:
- FDD auth.py의 쿠키 설정: `secure`, `samesite`, `httponly`
- `ENV=production` 환경변수 설정 여부
- HTTPS 활성화 여부 (secure=True 시 HTTPS 필수)
- 브라우저 개발자 도구 → Network 탭에서 `Set-Cookie` 헤더 확인

---

## 카테고리 12: 컨테이너 크래시

**증상**: 서비스 반복 재시작, docker ps에서 "Restarting"

**근본 원인**: OOM (메모리 초과), depends_on 누락, DB 연결 실패

**점검 대상**:
```bash
docker compose ps                              # 상태 확인
docker compose logs <service> --tail=100       # 에러 로그
docker stats --no-stream                       # 메모리 사용량
docker inspect <container> | grep -A5 "OOMKilled"  # OOM 확인
```
