# 지시 효율성 + 최적 프롬프트 피드백

분석 기간: 최근 $ARGUMENTS 일 (인자 미제공 시 기본값: 30일)

## 실행 순서

1. `logs/prompts.jsonl` 파일 존재 여부를 확인합니다.
   - 파일이 없으면 "지시 로그가 아직 없습니다. 작업을 진행하면 자동으로 지시가 기록됩니다." 안내 후 종료.

2. 분석 스크립트를 실행합니다:
   ```bash
   python .claude/skills/bug-feedback/scripts/analyze_prompts.py --days ${ARGUMENTS:-30}
   ```

3. 생성된 `knowledge/prompt-patterns.md` 파일을 Read합니다.

4. 다음 형식으로 피드백을 출력합니다:
   - **지시 통계** (총 지시 수, 세션 수, 평균 길이)
   - **카테고리별 분포** (implement, fix, review 등)
   - **반복 요청 TOP 5** (더 효율적인 방법 제안)
   - **세션 흐름 패턴** (implement→fix, fix→fix 등 비효율 패턴 감지)
   - **구체적 개선 제안**
   - **최적 프롬프트 피드백** (신규):
     - 프롬프트 성과 분류 (성공/재수정/에러 유발 비율)
     - 성공 vs 재수정 프롬프트 특성 비교표 (길이, 파일경로, 에러메시지, 구조화, 기대동작)
     - 데이터 기반 작성 규칙 (실제 로그에서 도출)
     - Before/After 실제 예시 (같은 세션 내 rework→개선 사례)
     - 안티패턴 목록 (피해야 할 프롬프트 유형)

5. 핵심 개선 제안이 있으면:
   - 해당 내용을 `CLAUDE.local.md`에 반영할지 사용자에게 확인합니다.
   - 반복 작업은 슬래시 커맨드로 자동화할 수 있는지 제안합니다.

## 출력 형식 예시

```
## 지시 효율성 피드백 (최근 30일)

### 요약
- 총 지시: 128건 | 세션 25개 | 평균 길이: 42자

### 카테고리 분포
| 카테고리 | 횟수 | 비율 |
|---------|------|------|
| implement | 48 | 38% |
| fix | 35 | 27% |

### 비효율 패턴 감지
- implement → fix (18회): 구현 후 수정이 빈번 → 플랜 모드 활용 권장
- fix → fix (12회): 연속 수정 → 에러 메시지 전체 첨부 권장

### 개선 제안
1. 수정(fix) 비율 27%: 구현 전 TDD 또는 플랜 모드 활용 권장
2. 키워드 "MA 워크플로우" 12회 반복: /ma-workflow 커맨드 자동화 고려

## 최적 프롬프트 피드백

### 프롬프트 성과 분류
- 분석 대상: 96건 (neutral 제외)
- 성공 (한 번에 완료): 48건 (50%)
- 재수정 필요: 32건 (33%)
- 에러 유발: 16건 (17%)

### 성공 vs 재수정 프롬프트 특성 비교
| 특성 | 성공 프롬프트 | 재수정 프롬프트 | 차이 |
|------|------------|--------------|------|
| 평균 길이 | 180자 | 45자 | +135자 |
| 파일 경로 포함 | 62% | 19% | +43%p |

### 데이터 기반 작성 규칙
1. **충분한 맥락 제공** — 성공 평균 180자 vs 재수정 45자
2. **파일 경로 명시** — 성공 62% vs 재수정 19%

### Before / After 예시
- Before: "이 모서리가 어색한데.."
- After: "파이프라인 첨부 이미지 부분도 User 탭과 동일하게 수정"
- 개선 포인트: 수정 위치 + 기준 명시
```
