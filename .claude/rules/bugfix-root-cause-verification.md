# Bugfix Root Cause Verification (RCV)

> **핵심**: 원인을 모르는 상태에서 수정하지 않는다. 원인을 "확인"하고 "확정"한 후에만 수정 계획을 세운다.

## 적용 시점

사용자가 다음을 요청할 때 **자동 적용**:
- 버그 수정, 에러 해결, 문제 해결
- "안 된다", "에러가 난다", "동작하지 않는다" 등의 문제 보고
- 테스트 실패, 빌드 실패, 런타임 오류

## 절대 금지

- "아마 ~일 것이다"로 시작하는 수정 계획
- "일단 ~을 바꿔보자" 방식의 시도-확인 수정
- 에러 메시지/스택 트레이스를 읽지 않고 수정 제안
- 관련 코드를 `Read`하지 않고 수정 제안
- 여러 가능한 원인을 동시에 수정 (산탄총식 수정)
- 원인 확정 전에 수정 코드 작성 또는 Edit/Write 호출

## 필수 절차 (원인 확정 게이트)

버그/문제 수정 요청을 받으면, **수정 계획 수립 전에** 반드시:

### 게이트 1: 증거 수집
- [ ] 에러 메시지/스택 트레이스 전문 읽기 (있는 경우)
- [ ] 관련 파일을 `Read`로 직접 읽기 (기억/추측 금지)
- [ ] 최근 변경 확인 (`git diff`, `git log`) — 해당하는 경우

### 게이트 2: 원인 확정 선언
수정 계획을 세우기 전에 다음 형식으로 원인을 **명시적으로 선언**:

```
근본 원인 확정:
- 위치: [파일명:라인번호]
- 원인: [구체적 설명]
- 확정 근거 (원칙적으로 5개, 명백한 경우 축소 가능):
  1. [근거 1]
  2. [근거 2]
  3. [근거 3]
  4. [근거 4]
  5. [근거 5]
```

**근거 수 기준:**
- **기본**: 최소 5개 — 대부분의 버그에 적용
- **명백한 경우**: 원인이 자명하면(에러 메시지가 정확한 위치와 원인을 직접 지목하는 경우 등) 5개 미만도 허용. 단, 왜 명백한지 한 줄로 설명 필수.

**근거를 충분히 채울 수 없으면:**
- 추가 증거 수집 (더 많은 파일 읽기, 로그 분석)
- 또는 사용자에게 재현 단계/추가 정보 요청
- **절대로 근거 부족 상태에서 수정 진행 금지**

### 게이트 3: 수정 범위 최소화
- 확정된 원인의 **정확한 위치만** 수정
- "하는 김에" 추가 수정 금지
- 원인과 무관한 코드 변경 금지

## "확정"의 정의

> **확정 = 이 코드를 수정하면 문제가 해결될 것이라는 근거를 최소 5개 제시할 수 있는 상태**
> 원인이 명백한 경우(에러가 위치와 원인을 직접 지목 등)에는 5개 미만도 허용하되, 명백한 이유를 명시한다.

근거를 충분히 채울 수 없으면 확정이 아니다. 추가 증거를 수집하거나 사용자에게 정보를 요청해야 한다.

## 확정 근거 유형 (아래에서 조합하여 최소 5개)

| 근거 유형 | 설명 | 예시 |
|----------|------|------|
| 코드 읽기 확인 | `Read`로 해당 코드를 읽고 문제 라인을 특정함 | "파일:42에서 null 체크 누락 확인" |
| 에러 메시지 일치 | 에러 메시지의 파일/라인이 실제 코드와 일치 확인 | "TypeError at line 42 → 해당 라인 Read로 확인" |
| 데이터 흐름 추적 | 잘못된 값의 출발점을 소스까지 역추적 | "호출자 A → B → C에서 undefined 전달 확인" |
| 패턴 비교 | 동작하는 유사 코드와 비교하여 차이점 특정 | "동작하는 X와 달리 Y에서 await 누락" |
| 재현 확인 | 문제를 재현하는 단계를 실행하여 동일 에러 확인 | "동일 입력으로 동일 에러 재현됨" |
| 의존성 확인 | import, 설정, 환경변수 등 외부 의존 요소 검증 | "패키지 버전 불일치 확인" |
| 타입/스키마 확인 | TypeScript 타입, DB 스키마, API 스키마 일치 검증 | "프론트 타입과 백엔드 응답 불일치 확인" |
| git 히스토리 확인 | 최근 변경이 문제를 도입했는지 커밋 기반 확인 | "커밋 abc123에서 이 줄이 변경됨" |
| 로그/출력 분석 | 런타임 로그, 콘솔 출력, 테스트 출력 분석 | "테스트 출력에서 기대값 vs 실제값 차이 확인" |

## 예외 (게이트 생략 가능)

다음은 자명하여 원인 확정 절차 없이 즉시 수정 가능:
- 오타 수정 (철자 오류, 변수명 오타)
- 단순 누락 (import 누락, 닫는 괄호/태그 등)
- 테스트 출력에 정확한 파일:라인과 기대값/실제값이 명시된 경우

## 에스컬레이션

- 수정 시도 **3회 이상 실패** 시 → `/systematic-debugging` 스킬 호출 필수
- 복잡한 멀티 컴포넌트 버그 → `/systematic-debugging` 스킬 호출 권장

## 위반 감지 신호

다음을 생각하거나 쓰려 한다면 **STOP — 게이트로 돌아가기**:
- "아마", "probably", "might be", "seems like"
- "일단", "한번 해보자", "바꿔보면"
- "여러 이유가 있을 수 있는데"
- "완전히 이해 못 하지만 이게 될 수도"
- "코드를 안 봤지만 ~일 것이다"
