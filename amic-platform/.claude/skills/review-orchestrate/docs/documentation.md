# Review Documentation Rule

> **목적**: 모든 오류 수정 및 리뷰 내역을 `review/` 폴더에 카테고리별로 정리하여 추적 가능성을 확보한다.

## 1. 필수 원칙

- **모든 오류 수정은 반드시 리뷰 문서를 남긴다.**
  - 버그 수정, 코드 리뷰 이슈 수정, 리팩토링, 보안 패치 등 모든 변경 포함
- **리뷰 문서는 `review/{카테고리}/` 폴더에 저장한다.**
  - 프로젝트 루트 기준: `review/`
  - 오류 종류에 따라 하위 폴더를 자동 생성
- **문서는 변경 직후 즉시 작성한다.** (사후 기록 금지)

## 2. 폴더 구조

```
review/
├── INDEX.md                    # 전체 리뷰 색인 (카테고리별 요약)
├── bugfix/                     # 버그 수정
│   ├── 20260217_1601_toast_error_feedback.md
│   └── ...
├── security/                   # 보안 취약점 수정
│   ├── 20260217_1602_cors_default_removal.md
│   └── ...
├── review/                     # 코드 리뷰 결과 및 수정
│   ├── 20260217_1603_full_frontend.md
│   └── ...
├── refactor/                   # 리팩토링
│   └── ...
├── a11y/                       # 접근성 개선
│   └── ...
├── perf/                       # 성능 개선
│   └── ...
└── hotfix/                     # 긴급 수정
    └── ...
```

### 카테고리별 폴더 자동 생성 규칙

- **문서 작성 시 해당 카테고리 폴더가 없으면 자동으로 생성한다.**
- 폴더 생성 명령: `mkdir -p review/{카테고리}`
- 새 카테고리가 필요한 경우 이 규칙 파일의 카테고리 목록에 추가 후 생성

### 카테고리 목록

| 카테고리 | 폴더명 | 설명 | 예시 파일명 |
|---------|--------|------|------------|
| 버그 수정 | `bugfix/` | 기능 오류, 런타임 에러, 논리 오류 수정 | `20260217_1601_toast_error_feedback.md` |
| 보안 | `security/` | 보안 취약점, 인증/인가 이슈, XSS/CSRF 등 | `20260217_1602_cors_default_removal.md` |
| 코드 리뷰 | `review/` | 종합 코드 리뷰 결과 및 수정 내역 | `20260217_1603_full_frontend.md` |
| 리팩토링 | `refactor/` | 코드 구조 개선, 패턴 통일, 중복 제거 | `20260217_1604_api_client_consistency.md` |
| 접근성 | `a11y/` | WCAG 기준 개선, aria 속성, 키보드 네비게이션 | `20260217_1605_pagination_aria_label.md` |
| 성능 | `perf/` | 렌더링 최적화, 쿼리 최적화, 번들 크기 | `20260217_1606_query_optimization.md` |
| 긴급 수정 | `hotfix/` | 프로덕션 장애, 긴급 패치 | `20260217_1607_production_crash.md` |
| 타입 | `type/` | TypeScript 타입 오류, 타입 안전성 개선 | `20260217_1608_generic_type_fix.md` |
| 빌드 | `build/` | 빌드 에러, 설정 오류, 의존성 문제 | `20260217_1609_vite_config_fix.md` |
| UI/UX | `ui/` | 스타일 수정, 레이아웃 깨짐, 디자인 불일치 | `20260217_1610_sidebar_overflow.md` |

## 3. 파일명 규칙

```
review/{카테고리}/YYYYMMDD_HHMM_{요약}.md
```

- 카테고리 접두사 불필요 (폴더가 카테고리를 나타냄)
- 요약은 snake_case, 영어로 작성 (파일 시스템 호환)
- 타임스탬프는 PowerShell `Get-Date -Format "yyyyMMdd_HHmm"` 또는 `date +"%Y%m%d_%H%M"`

## 4. 문서 템플릿

```markdown
# {요약 제목}

- **날짜**: YYYY-MM-DD HH:MM:SS
- **카테고리**: {카테고리}
- **작성자**: {작성자}
- **관련 이슈**: {이슈 ID 또는 "N/A"}
- **심각도**: Critical / High / Medium / Low
- **상태**: 수정 완료 / 부분 수정 / 검증 대기

## 변경 요약

{1-2문장으로 무엇을 왜 변경했는지 요약}

## 변경 파일

| 파일 경로 | 변경 유형 | 설명 |
|----------|----------|------|
| `path/to/file.ts` | 수정 | {변경 내용 요약} |

## 변경 상세

### {변경 1 제목}

- **파일**: `path/to/file.ts:라인번호`
- **변경 전**: {기존 코드 또는 동작 설명}
- **변경 후**: {수정 코드 또는 동작 설명}
- **사유**: {왜 이 변경이 필요했는지}

## 검증

- {추가 검증 항목}

## 영향 분석

- **영향 범위**: {변경의 영향을 받는 모듈/컴포넌트}
- **하위 호환성**: 유지 / 깨짐 (사유: ...)
- **추가 조치 필요**: 없음 / {필요한 조치}
```

## 5. 적용 범위

### 반드시 문서화해야 하는 경우

1. **코드 리뷰 이슈 수정** → `review/review/` — VCP 이슈 ID 참조 포함
2. **버그 수정** → `review/bugfix/` — 원인 분석 + 수정 내용 + 재발 방지책
3. **보안 취약점 수정** → `review/security/` — 취약점 유형, 수정 방법
4. **접근성 개선** → `review/a11y/` — WCAG 기준 참조
5. **성능 개선** → `review/perf/` — 개선 전후 측정값 (가능한 경우)
6. **긴급 수정** → `review/hotfix/` — 장애 타임라인, 근본 원인, 수정 내용
7. **타입 오류 수정** → `review/type/` — 타입 오류 내용, 수정 방법
8. **빌드 오류 수정** → `review/build/` — 빌드 에러 메시지, 해결 방법
9. **UI/UX 수정** → `review/ui/` — 시각적 변경 설명

### 문서화 생략 가능한 경우

- 단순 오타 수정 (코드 동작에 영향 없음)
- 주석/문서 수정만 있는 경우
- 자동 포매팅 변경 (prettier, eslint --fix)

## 6. 리뷰 색인 (INDEX.md)

`review/INDEX.md`를 유지하여 전체 리뷰 내역을 한눈에 파악할 수 있도록 한다.

### INDEX.md 형식

```markdown
# Review Index

> 최종 업데이트: YYYY-MM-DD HH:MM:SS

## 카테고리별 요약

| 카테고리 | 총 건수 | 최근 문서 |
|---------|--------|----------|
| bugfix | 3건 | `20260217_1601_toast_error_feedback.md` |
| security | 2건 | `20260217_1602_cors_default_removal.md` |
| ... | ... | ... |

## 전체 내역 (최신순)

| 날짜 | 카테고리 | 요약 | 심각도 | 파일 |
|------|---------|------|--------|------|
| 2026-02-17 | security | CORS 기본값 제거 | High | [링크](security/20260217_1602_cors_default_removal.md) |
| 2026-02-17 | bugfix | Toast 에러 피드백 추가 | Medium | [링크](bugfix/20260217_1601_toast_error_feedback.md) |
```

- 새 리뷰 문서 생성 시 INDEX.md에 항목 추가
- 카테고리별 요약 건수 업데이트
- 날짜 내림차순 정렬 (최신이 위)

## 7. 워크플로우 통합

### 코드 리뷰 스킬 연동

`review-orchestrate` 스킬 실행 시:
1. Phase 3 (이슈 수정) 완료 후 → 카테고리별로 수정 내역 문서 자동 생성
2. 복합 이슈인 경우 → 주 카테고리 폴더에 생성, 관련 카테고리 태그 명시
3. INDEX.md 업데이트

### 일반 버그 수정 워크플로우

1. 오류 발견 → 원인 분석
2. 코드 수정
3. 검증 (테스트, 빌드)
4. 카테고리 판별 → 해당 폴더 존재 확인 (없으면 `mkdir -p`)
5. `review/{카테고리}/` 폴더에 문서 작성
6. INDEX.md 업데이트

### 카테고리 판별 기준

- 보안 관련 키워드 (XSS, CSRF, 인증, 토큰, CORS) → `security/`
- 접근성 키워드 (aria, WCAG, 스크린리더, 키보드) → `a11y/`
- 타입 오류 (TypeScript, 제네릭, 타입 단언) → `type/`
- 빌드/설정 (webpack, vite, tsconfig, package.json) → `build/`
- UI/스타일 (CSS, Tailwind, 레이아웃, 반응형) → `ui/`
- 성능 (렌더링, 메모이제이션, 번들, lazy) → `perf/`
- 기능 오류 (런타임 에러, 논리 오류) → `bugfix/`
- 구조 개선 (패턴 통일, 중복 제거) → `refactor/`
- 종합 리뷰 → `review/`
- 프로덕션 긴급 → `hotfix/`
