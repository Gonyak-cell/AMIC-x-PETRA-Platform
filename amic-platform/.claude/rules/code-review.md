# Code Review Verification Rules

> **필수 참조**: 모든 코드 리뷰 에이전트는 **Verified Claim Protocol** (`.claude/rules/verified-claim-protocol.md`)을 적용합니다.
> 이 파일의 6개 원칙은 VCP의 보충 규칙으로 함께 적용됩니다.
>
> **문서화 필수**: 모든 오류 수정 및 리뷰 내역은 **Review Documentation Rule** (`.claude/rules/review-documentation.md`)에 따라 `review/{카테고리}/` 폴더에 기록합니다.

## 코드 리뷰 시 할루시네이션 방지 규칙

### 1. 사실 기반 리뷰 원칙
- 이슈를 보고할 때 반드시 **파일 경로 + 라인 번호**를 포함
- "~인 것 같다", "아마 ~일 것이다" 등 추측성 표현 금지
- 코드를 직접 Read한 후에만 이슈를 기술
- 읽지 않은 파일에 대한 이슈 보고 금지

### 2. 수치 정확성
- "N개 파일", "M건 이슈" 등 수치를 기술할 때 실제 카운트 수행
- 이전 세션의 수치를 그대로 인용하지 않고 현재 상태 재확인
- 테스트 수, 파일 수 등은 Glob/Grep으로 직접 카운트

### 3. 이슈 ID 참조
- 기존 리뷰 문서의 이슈를 참조할 때 원본 문서를 Read하여 ID 확인
- 이슈 번호, 심각도, 설명이 모두 일치하는지 교차 검증
- 존재하지 않는 이슈 ID 참조 금지

### 4. 코드 패턴 주장
- "X 패턴을 사용한다" → Grep으로 실제 존재 확인
- "Y가 없다" → Grep으로 부재 확인 (False Negative 주의)
- 한 파일에서 본 패턴을 다른 파일에 일반화하지 않음

### 5. 리뷰 문서 자체 검증
- 리뷰 완료 후 `review-verifier` 에이전트로 자체 검증 권장
- 특히 수치, 파일 경로, 이슈 참조는 반드시 재확인
- False Positive(존재하지 않는 문제 보고)는 신뢰도를 크게 훼손

### 6. 수정 검증
- "수정됨" 판정 시 반드시 현재 코드를 Read하여 확인
- 이전 리뷰의 수정 여부를 추측하지 않고 실제 검증
- git diff가 가능하면 커밋 내역도 확인

### 7. 수정 내역 문서화
- 오류 수정 후 반드시 `review/{카테고리}/` 폴더에 수정 내역 문서 작성
- 카테고리 폴더가 없으면 자동 생성 (`mkdir -p review/{카테고리}`)
- 문서 작성 후 `review/INDEX.md` 업데이트
- 상세 규칙: `.claude/rules/review-documentation.md` 참조
